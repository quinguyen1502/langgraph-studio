## How the rules were applied

| Rule | Where |
|---|---|
| Layers | Engine only reports usage through a callback (`engine/usage.py`, `call_llm(on_usage)`, `node_fn(usage)`); it has no tracing code. Tracing and metrics live in `services/telemetry.py`. `RunService` receives `Telemetry` by injection (`api/deps.get_telemetry`). |
| One path (DRY) | LangSmith is just another OTLP exporter. `summarize()` gives the same numbers to the DB, the trace and the UI. The UI uses one `run_summary` event shape live and for history (`withSummary`). One price table. |
| KISS | Spans are built after the run from event timestamps. No global tracer, no auto-instrumentation, no SDK import when disabled. |
| Envelope / codes | No new error codes. History and health keep the envelope; tracing errors never reach the client. |
| i18n / shadcn | New strings in `en.json` and `vi.json` (plural keys). Badge, Button asChild, Tooltip and lucide icons with theme tokens only. The history row shows an icon, not a nested link (no `<a>` inside `<button>`). |
| Ownership | History is still owner-only (tested); spans carry the user id, not the email. |

## Findings / open

- Spans are exported when the run ends; a long run shows nothing in Jaeger until it finishes.
- LangSmith export was verified for configuration and headers only (no key on the box). With `LANGSMITH_TRACING=true`, LangChain's native tracer may also send its own LangGraph runs (duplicates). If that is noisy, a follow-up could disable the native tracer per run.
- The price table is static and will drift; unknown models show `—`. No env override yet.
- Token counts for mock and for providers without `usage` are estimates (flagged `estimated`).
- No metrics export (OTel metrics / Prometheus) yet; only traces and per-run DB columns. Aggregated error rates would be a query over `runs`.
