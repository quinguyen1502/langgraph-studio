### Non-Blocking

- Fixed during review: the parallel-writes check treated a For each node's two edges as parallel branches. It could report "Parallel nodes … write" when the body and the node after `done` wrote the same field. For each is now skipped like Condition. Covered by `test_each_and_done_are_not_parallel_branches`.
- The loop channel is declared on the compiled `State`, so LangGraph keeps it on resume and recovery input. `test_human_pause_inside_the_loop_resumes_at_the_same_item` exercises this. The run output strips it.
- The router depends only on the position the node just wrote (0 means done), so it cannot disagree with the node function.
- The step budget is an upper bound: the body is every node reachable from `each` without passing the loop. It is capped at 100,000, so a bad graph cannot ask LangGraph for unbounded steps.
- The `loop:` prefix cannot clash with a user field because the validator reserves it.
- The editor's auto-label uses `rf.getNode` inside the `setEdges` updater, and the edge list it checks is the updater's own argument, so two quick connects get `each` then `done`.
