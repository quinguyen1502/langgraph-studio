# UI conventions (DEC-0008)

Applies to all frontend code in `frontend/src`. Coding agents and reviewers must follow it.

## Rules

1. **Use shadcn/ui components only.** When shadcn has a component for the job, use it rather than building your own: Button, Badge, Tabs, Collapsible/Accordion, ScrollArea, Tooltip, Separator, Switch/Toggle, Alert, Dialog, DropdownMenu, Table, Input, Select, Progress, Resizable, and so on.
   - Add missing components with the CLI: `cd frontend && npx shadcn@latest add <name>`.
   - The CLI currently writes files to a literal `@/` folder. Move them into `src/components/ui/` and keep the project's `cn` import (`from "cn"`).
   - Only customise a component through its `cva` variants, the way shadcn does it (for example, the `success`/`warning` variants on Badge).
2. **Use theme tokens only.** Allowed tokens include `bg-background`, `bg-card`, `bg-muted`, `bg-accent`, `bg-secondary`, `text-foreground`, `text-muted-foreground`, `border`, `ring`, `primary`, `destructive`, `chart-*` and `sidebar-*`. Opacity modifiers such as `bg-destructive/10` are fine.
3. **No hard-coded colours.** That means no `red-500`, `emerald-600`, `amber-*`, `text-white`, `bg-black` or hex/rgb values in components. The only exceptions are files generated by shadcn, such as the dialog overlay.
4. **New semantic colours become CSS variables**, following shadcn's naming. Define them in `src/index.css` for both `:root` and `.dark`, and map them in `@theme inline` (as `--color-<name>`). Tokens already defined:

   | Token | Use |
   |---|---|
   | `success` / `success-foreground` | done, ok, passed |
   | `warning` / `warning-foreground` | running, pending, changed |
   | `info` / `info-foreground` | neutral highlights, such as JSON numbers |
   | `destructive` | errors (shadcn built-in) |

5. **Node types each have a colour token** (DEC-0008 addendum). Each type has three tokens: `--node-<type>` (accent), `--node-<type>-foreground` (text on a solid accent) and `--node-<type>-muted` (subtle background, the accent at 12% in light and 18% in dark). Types are `start`, `llm`, `tool`, `condition`, `end` and `code`.
   - Example classes: `bg-node-llm-muted text-node-llm` (icon chip), `bg-node-llm` (accent stripe), `border-node-code/60` (Code node border).
   - Use them in the palette, canvas node cards, the config header and trace timeline icons. They come from one map (`META` in `Editor.tsx`), so don't copy the classes elsewhere.
   - Light values sit at about oklch L 0.5–0.64 so they contrast with white; dark values sit at about L 0.7–0.8, with dark foreground text.
   - Node-type colours mean *category*, not status. Status keeps using `success`/`warning`/`destructive`.

6. **Dark mode must work.** Use tokens only (never `dark:` colour overrides), and check that the screen looks right in both themes.

## Review checklist

- [ ] No custom widget where shadcn has a component.
- [ ] This command finds no hard-coded colours:
  `rg -n "(text|bg|border|ring)-(red|emerald|green|amber|yellow|orange|sky|blue|violet|purple|teal|zinc|gray|slate)-[0-9]|text-white|bg-white" frontend/src --glob '!components/ui/**'`
- [ ] Screenshots are taken in both light and dark mode for UI changes.
