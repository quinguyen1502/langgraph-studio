### Non-Blocking

- Layers: routes set and clear the cookie (HTTP), `AuthService` holds the rules, `AuthSecurityRepository` the SQL. No FastAPI in services.
- `current_user` prefers a Bearer header, so API clients and webhooks are unchanged. The CSRF check applies only when the cookie authenticated the request, and only to unsafe methods.
- Lockout: a locked e-mail is refused before the password check and further attempts do not extend the lock. The window resets after a lock. Rows are pruned on each failure.
- Reset: the token is 32 random bytes and only its SHA-256 is stored. `use_reset` marks the link used and sets the password in one transaction, guarded by `used IS NULL`, so two parallel uses cannot both succeed. Other open links of the account are deleted.
- Session invalidation compares the whole-second `iat` with `int(password_changed)`. A token made in the same second as the change survives; the specs wait one second to test the boundary.
- `request_reset` returns `{"reset": "email"|"admin"}` from configuration only, and the e-mail is sent on a background thread, so neither the answer nor its timing depends on the address.
- Seed: production creates no demo user, and deactivates one that still verifies with the demo password. Legacy rows and the example then go to the oldest active admin; with no admin they are left alone.
- `mailer.send` is shared with notification e-mail (which had the same SMTP code inline).
- The socket origin check compares host names without ports because nginx forwards `$host`; a page on another port of the same host is same-site anyway.
- The reset link is returned as a path, and as a full URL only when `STUDIO_PUBLIC_URL` is set. Behind the Vite proxy (and any proxy that rewrites `Host`), the API cannot know the page's origin.
- Email is never put in a URL; the sign-in and reset pages pass it in router state.
