### Non-Blocking

- `cron.next_time` walks days, then the sorted hours and minutes of matching days, so it never iterates minute by minute; a Feb 29 search over years takes about 2 ms. It stops after five years (`None`), which turns a schedule off with `note="invalid"`.
- Local times are converted with `fold=0`: a skipped time maps to the hour after, and a repeated time to its first occurrence. Tests cover both New York transitions.
- `claim` compares the stored float `next_run`; the value read is the value written, so the comparison is exact on SQLite and Postgres.
- `fire_due` computes the next time after now, not after the missed time, so a long outage gives one run, not a backlog.
- The worker previously wrote `source="api"` for every queued run; it now uses `job["source"]`, defaulting to `api` for jobs already in a queue.
- Rights follow API tokens (`share`). The UI shows the entry only to the owner, also like tokens; admins can use the API.
- The preview endpoint needs a signed-in user but no workflow, and runs only the parser.
- Deleting a workflow does not delete its schedules at once; the scheduler removes them at their next due time. This keeps `WorkflowService` unchanged; the API tokens of a deleted workflow behave the same way.
