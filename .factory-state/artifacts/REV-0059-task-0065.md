## Findings

### Blocking

- None.

### Non-Blocking

- **One gate for "first answer wins".** The editor (`plan_resume`), a channel button (`_decide`, also for e-mail and
  Teams links) and the inbox each close the waiting step with a compare-and-set. The loser is refused before any job
  is queued. Runs that paused before the migration have no row; `claim` lets them through, so they keep working from
  the editor and channels as before. Tested for editor versus inbox and inbox versus Slack.
- **What an approver sees.** The inbox row carries the request only. Its question is the Human node's rendered
  prompt, which can include state values through `{{state.…}}`. That is the same text the channel message already
  shows, so DEC-0043 counts it as part of the request. An author who does not want approvers to see a value should
  leave it out of the prompt; the handbook's description of the row covers this implicitly.
- **Inbox answers need the job queue.** `answered_in_studio` queues the `resume` job like a channel decision. The
  service in `deps.py` always has `enqueue`, and a worker in any API process (or a separate one) runs it. Recorded in
  DEC-0043 consequences.
- **`can_open`** follows the run history rule: the run owner, and the workflow's owner or an admin
  (`access_of == "owner"`). Tested for an admin approver and a plain approver.
- **Workflows page.** The list moved to `/approvals`; the Workflows card keeps the count with a link, so there is one
  list. The header entry now shows at 0 too, so the page is always reachable; the count badge appears only above 0.
- **Polling.** The header badge and the Workflows card each poll the inbox every 30 s and on focus. On the Workflows
  page that is two small requests per tick; acceptable, and the same cadence as before.
- **Unrelated local failure.** `tests/test_code_node.py::test_docker_time_and_memory_limits` failed once in a full
  local run while the disk was nearly full, and is skipped alone (Docker not on PATH). No code here touches the Code
  node runtime. CI is the reference.
