### Blocking

### Non-Blocking

- The parser is a regex plus a fixed filter table; there is no evaluation of user text. Filter arguments are a quoted string or an integer, so `truncate('x')` and `upper(1)` are reported, not coerced.
- `render` and `render_args` keep their signatures; `nodes.py` is unchanged. The old `VAR_RE` group 1 is still the field name.
- Behaviour change: an existing field holding `None` renders `""` instead of `null` (DEC-0034 Impacts).
- Validator: one `template_errors` helper over `templates_of(type, data)`, which mirrors the fields `nodes.py` renders. MCP arguments are checked string by string, so quotes inside a filter argument are not JSON-escaped before matching. Messages are de-duplicated.
- The Human prompt and HTTP URL and body were not checked before; a workflow that referenced a missing field there now gets a save error. It already rendered empty at run time.
- `TEMPLATE_INVALID` was taken (template files). The duplicate dict key silently replaced the message; `test_templates.py` caught it. The new code is `TEMPLATE_REF_INVALID`.
- Editor: `MatchDecorator.decorate` skips the reference being edited; the edit range is a `StateField` that maps through changes and clears once the cursor leaves it. The whole set is recomputed only when that field changes.
- Filter completion inserts `default("")` / `truncate(20)` with the cursor inside the argument.
- The shared fixture is read by pytest and imported as JSON by vitest, so both parsers are tested on the same cases.
