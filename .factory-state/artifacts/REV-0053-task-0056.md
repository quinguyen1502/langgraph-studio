## Findings

### Blocking

- No blocking findings.

### Non-Blocking

- **What subprocess mode does and does not protect.**
  - The child gets an empty environment (secrets of the server process stay out) and its own temporary folder, which is removed afterwards.
  - It runs in its own session, and a timeout or a cancel kills the whole group; a test shows a grandchild `sleep` dies too.
  - On Linux, rlimits apply: memory, CPU, open files and processes.
  - The child runs `sys.executable -I`, so it can import the server's installed packages, including `app`. It cannot reach the server's memory.
  - Its file access is what the server user has. The README names the database file and `secret.key` of a SQLite setup as readable.
  - **This is the accepted residual risk of REQ-0039 Host Subprocess Mode.**
- **`RLIMIT_NPROC`** counts every process of the server user, not only the child's. A busy host user can make the child's own `fork` fail sooner. This is acceptable for a trusted-local mode.
- **No fallback.** The default runtime stays `docker`. An unknown value is `off`, and `docker` without Docker fails validation (`test_no_silent_fallback_from_docker`).
- **The eight warnings, one source.**
  - The UI reads `code_runtime` only from `GET /api/meta/runtime`.
  - Trace rows use `code_output.runtime`, and run history uses the stored `runs.code_runtime`, which is `subprocess` if any call in the run was unisolated.
  - The audit entry is written once per process: the flag is per worker process, as TASK-0056 allows. The actor is the person running, or the tester for Test with sample state.
- **Badge id.** The mode-picker badge uses `data-testid`, because Radix renders the selected item's content again in the trigger. Two identical `id`s were caught by the e2e run.
- **Migration.** `0029` adds a nullable text column and is idempotent like `0028`. Older runs read `null`, meaning no Code node.
