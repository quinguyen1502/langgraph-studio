## Findings

### Blocking

- None.

### Non-Blocking

- **Fixed during review: a settled state replied more than once.** `mark_replied` matched its own value when
  `settled()` ran again for the same state (CAS from `ok` to `ok`). It now returns early when the state was already
  replied. The test calls `settled()` twice.
- **The URL check is answered without a signature.** Slack's `url_verification` carries no `team_id`, so no
  connection can verify it. Echoing the platform's own value reveals nothing, and the value is capped at 200
  characters. Every message event is verified against the connections of its workspace.
- **Telegram refusals in a group.** Telegram has no message that only one group member sees. A direct message works
  once the sender has started the bot; otherwise the refusal goes to the group. Refusal texts hold nothing private.
- **A dead worker between claim and start.** The message stays `checking` and starts nothing, rather than risking
  two runs. The sender can write again.
- **Audit action labels.** The Settings → Audit list shows `chat_started` and `chat_refused`. The frontend labels
  and filters for them come with TASK-0076.
- **Ignored events are not verified.** Events that are not messages are answered `ignored` before any signature
  check. This does no work and reveals nothing.
