## Findings

### Blocking

- None open. One was found and fixed during review (below).

### Fixed During Review

- **An upgrade could start a second stack.** With the Compose project renamed, `docker compose up` on a host where the
  v0.1.0 stack is still running creates `superstep-*` containers next to the `langgraph-studio-*` ones: the ports
  collide, and if they did not, two Postgres servers would open the same pinned volume. Fixed with an
  "Upgrade from v0.1.0" section in `operate/deploy.md` (en/vi): run `docker compose -p langgraph-studio down` first.
  Checked: that command, run from the new checkout, removed the old project's containers and kept its volume.

### Non-Blocking

- **Visible changes for operators**, now listed in the upgrade section and to be repeated in the v0.2.0 notes:
  - the default `OTEL_SERVICE_NAME` is now `superstep`, so dashboards filtered on the old name need it set back;
  - e-mail subjects start with `[Superstep]`;
  - container and network names start with `superstep-`.
- **`Clip.format` type.** `parseClip` now also returns payloads whose `format` is `langgraph-studio/nodes`, while the
  type says `typeof CLIP_FORMAT`. Nothing reads `format` after parsing, so this is a typing gap only.
- **`TEMPLATE_FORMAT` in `frontend/src/lib/templates.ts` is not used** anywhere (it was not before this task either).
  Renamed for consistency, left in place.
- **The README badges and docs links return 404 until the repository is renamed.** This is expected and called out in
  the PR's merge order.
- **The CI job "Backend (pytest on Postgres 17 + Redis 7)" failed once** on `test_disconnect_cancels_run`: the run list
  was still empty after 10 s. The same test failed on `develop` at 13:01 on 2026-10-19, before this task, so it is a
  flaky test and not caused by the rename. The job was re-run.

- **Layers (DEC-0009):** `home_dir` lives in `core/config.py` with the other environment-derived settings; `crypto` and
  `repo_import` call it. No FastAPI in services, no SQL, no schema change.
- **Errors:** the changed `APPROVAL_IDENTITY_UNKNOWN` message is updated in `CATALOG`, `docs/api-errors.md` and both
  locales together; `test_api_envelope.py` passes.
- **UI (DEC-0008):** text only; no new components or colours; en/vi keys stay identical. The brand name stays a literal
  in three components, as it was before.
- **DRY:** one helper for the data directory, one tuple (`FORMATS`) per accepted legacy format.
- **Compatibility:** the old template and clipboard formats, the old key directory, the HMAC prefix and the volume names
  each have a test or a recorded check (see QA-0054).
