## How the rules were applied
- Layering: `core/permissions.py` (pure matrix) → `AccessService` (the single check) → workflow, run, trigger, delivery, share and user services → thin routes. A `need(permission)` route dependency guards resource-creating endpoints. Repositories contain queries only.
- DRY: every former `get_owned` call goes through `AccessService`. Add to Slack reuses `ChannelService.create` (same validation, `auth.test` and admin rules as a pasted token).
- KISS: three fixed roles in code, shares by e-mail, no groups.
- Envelope + English codes: 13 new codes (catalog, docs/api-errors.md, en/vi).
- Migration `0021_rbac`: SQLite + Postgres, with a backfill test on both.
- Strict shadcn: Table/Select/Switch/Dialog/Badge only, tokens only.

## Security
- Accounts are DB-checked per request and per WebSocket, so deactivation takes effect immediately. Guards against changing your own role and against removing the last admin.
- Shared runs use the owner's resources; non-editors cannot inject graph JSON; private run history.
- The OAuth state is HMAC-signed with a 10-minute expiry, the account is re-checked on callback, and the client secret is sent only to Slack.
