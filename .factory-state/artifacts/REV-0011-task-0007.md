## Findings / open

- Webhooks are not signed (no HMAC header yet), and there is no delivery log or retry beyond 2 attempts.
- In-memory queue: jobs are lost if the API process restarts (the row stays `queued`). With Redis, a job taken by a worker that crashes mid-run is lost too (no visibility timeout / ack).
- Sync mode holds an HTTP connection up to `STUDIO_RUN_TIMEOUT + 5` s.
- No rate limiting per token.
- The SSRF guard resolves DNS at request time; DNS rebinding between check and delivery is not prevented.
- Test fix: `studio.spec.ts` expired-token test now waits for network idle before swapping the token. The extra pending-runs request from TASK-0006 made it race (the ERR_ABORTED flake noted in REV-0010).

## Follow-up: TASK-0019 (phase-2 hardening, DEC-0016)

- **Resolved**: HMAC-SHA256 signatures (`X-Studio-Signature: t=…,v1=…`, per-token secret, documented verification with a 5-min tolerance).
- **Resolved**: per-token rate limit (`RATE_LIMITED` 429 + `Retry-After`; Redis or in-memory).
- **Resolved**: reliable Redis queue (BLMOVE → per-worker processing list, ack, heartbeat, requeue of dead workers' jobs on start). The in-memory queue is documented as dev-only.
- **Resolved**: sync wait capped by `STUDIO_SYNC_WAIT_MAX`, then 202 + `poll_url` / `Location`.
- **Resolved**: DNS rebinding. Resolve once, validate every address, connect to the pinned IP (Host + SNI preserved), no redirects.
- **Still open**: tokens created before TASK-0019 have no signing secret (unsigned; create a new token); no delivery log.
