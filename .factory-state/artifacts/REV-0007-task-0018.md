## How DRY / SOLID / KISS were applied

| Rule | Where |
|---|---|
| One error type and one catalog | `core/errors.py`: `AppError` + `CATALOG`. The old six exception subclasses were removed. |
| One success wrapper | `schemas/envelope.py` `EnvelopeResponse` as FastAPI `default_response_class`. Routes are unchanged and return plain data. |
| One handler set | `api/error_handlers.py`: AppError, 422, HTTP 404/405, Exception→500. No route-level try/except. |
| One WS error shape | `run_service.error_event` + `_normalise` (engine events gain `error`). |
| One client unwrap | `frontend/src/lib/api.ts` `api()`. |
| One translation path | `lib/i18n.ts` `errorText` / `eventErrors`. All UI strings are in `locales/{en,vi}.json`. |
| Parity tests | `test_api_envelope.py`: catalog ↔ `docs/api-errors.md` ↔ both locales, and identical en/vi keys. |
| KISS | No generic Envelope[T] models per route, no error-code enum class, no i18n namespaces. Template params double as `details` so clients can interpolate. |

## Findings / open

- Validator issues and node/runtime exception messages are English free text (in `details`/`errors`) and are not translated per issue.
- Existing E2E specs run with `locale: vi-VN`; the new `i18n.spec.ts` covers English.
- Breaking for external API users: they must read `data`.
- Screenshots were not retaken for the new language switcher.
