## Summary of Changes

- Backend `compiler.run_stream`
  - Events gain `node_type` and `iteration`, and `node_finished` gains `input` (state before the step).
  - `cap_payload` truncates any payload over 16 000 JSON characters to a preview marker.
  - Runtime exceptions become an `error` event attributed to the running node.
  - `STUDIO_RECURSION_LIMIT` defaults to 25.
- Backend `main.py`: `run_started` carries `ts` and is stored with the run.
- Frontend
  - `lib/trace.ts`: `buildTrace` creates one span per execution, numbers loop iterations, drops speculative never-run rows when the run ends, computes the waterfall, and provides `stateDiff`.
  - `components/run-trace.tsx`: summary, rows, detail tabs, Raw events toggle.
  - `components/json-view.tsx`: collapsible JSON with copy.
  - `Editor.tsx`: canvas↔row sync and node highlight; History replay shows a "Replay" badge; run panel is 300 px tall.

## Findings

- The protocol change is additive; old stored runs replay without `input`, and the Input tab shows "no data".
- The default langgraph recursion limit in this version was ~10 000, so a looping run produced ~20k events before failing. It is now capped at 25. This overlaps TASK-0004 (runtime hardening).
- Tokens are displayed only when events include them; the mock LLM emits none.

## Risks

- `input` roughly doubles stored event size per node (bounded by the cap).
