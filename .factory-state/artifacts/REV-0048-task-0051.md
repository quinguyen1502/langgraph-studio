### Non-Blocking

- Secrets: the password is the existing Fernet secret and never leaves `resolve()`. `test_run_sends_one_message_with_cc_bcc_and_reply_to` asserts it is not in any run event; SMTP error reasons carry the server's reply code and text, not the credentials.
- SSRF: SMTP credentials resolve the host once, refuse private, loopback, link-local and reserved addresses unless `STUDIO_SMTP_ALLOW_PRIVATE=1`, and connect to the checked IP while TLS verifies the host name. The admin's own `SMTP_HOST` keeps working on private addresses.
- Header injection: subjects are folded to one line, addresses are parsed and checked one by one, and Bcc is only in the SMTP envelope.
- HTML: values inserted from the state are escaped; the template's own markup is the author's.
- Sending twice: the ledger reuses the recorded result on recovery, the Message-ID comes from the idempotency key, and the validator refuses `retry` / `cache_ttl` on this node type (found during this review and fixed).
- Credential update without `settings` now keeps the stored settings instead of failing (found during this review and fixed).
- `test_notify_webhook_signed` (existing) could read a late webhook sent by the previous test's background thread. It is now matched by run id; the mailer also builds its TLS context only when TLS is used, which made the race visible.
- The quota counts recipients in a fixed hourly window per resource owner; a refused attempt still counts. Acceptable for an abuse cap.
