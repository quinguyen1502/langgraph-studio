## How the rules were applied
- Layering: engine-only logic in `engine/reducers.py` and `engine/subgraphs.py` (pure functions, no I/O). Services bind the loader to the user (`RunService._expand`, `WorkflowService.validate`). Routes only delegate (`POST /api/validate` now goes through the service).
- DRY: one set of reducer functions serves LangGraph channels and runtime state tracking. Subgraph validation and expansion share `check()`.
- KISS: subgraphs are expanded inline instead of nesting compiled graphs, so the existing HITL, checkpoint, recovery and ledger paths cover inner nodes unchanged.
- No new API error codes: reference problems are `WORKFLOW_INVALID` with English detail strings, as for other validation errors. No database change, so no migration.
- Strict shadcn: new `--node-join` / `--node-subgraph` theme tokens (light and dark); components use only tokens. en/vi for every new text.

## Security
- Subgraph references resolve only to the user's own workflows. Another user's id behaves like a missing workflow, so ids are not disclosed. Imported (code) workflows cannot be embedded.
- Bounded expansion: depth ≤ 5, cycles rejected. The existing workflow size limit still applies to the parent; the expanded size is bounded by depth × the child limits.

## Open issues
- Inner-node validation messages use prefixed ids (`sub/sum`). The canvas cannot jump into the child: "Open workflow" navigates instead.
- A child edit does not create a parent version; the run version tag covers the parent only.
- Send-API (dynamic map-reduce) is out of scope (REQ-0006).
