### Non-Blocking

- **Fixed after review (PR #87 check, 2026-10-21): timeout closed the run's step, not the swept one.** `_timeout` closed
  whatever step of the run was open (`close_wait(run_id)`). A sweep that read step A just before A was answered could,
  if the run had already paused at a later Human node B, close B and resume it with the timeout answer. The timeout
  now closes only the swept step (`close_wait(run_id, "deadline", wid)`); if A is still open, the run still waits
  at A, so `close_run` and the resume job act on the right step. Test: `test_late_sweep_leaves_a_later_step_alone`
  (fails before the fix).
- **Fires once.** Reminders are claimed on `next_remind_at`, escalation on `escalated_at IS NULL` and `due_at`, and
  the timeout through the same `close_wait` gate every answer uses (DEC-0043). Four parallel sweeps fire one
  reminder in the test. Skipped escalation addresses are logged only by the sweep that wins, fixed during review.
- **Catch-up after downtime.** A late sweep sends one reminder, not every missed one, and the next one is counted from
  now. A passed deadline fires on the first sweep.
- **Reminders and the deadline.** No reminder is scheduled at or after the deadline, and at most 5 are sent
  (`MAX_REMINDERS`). Escalation resets the count for the new approvers.
- **Snapshot.** The deadline and the channel settings are copied onto the waiting step from the run's own workflow
  snapshot, so editing the workflow while a run waits does not change that run. A loop back to the same node writes a
  new step and starts a new deadline.
- **Parallel Human nodes.** The runtime pauses at the first Human node that interrupts, so a run has one waiting step
  at a time. Each later pause gets its own deadline. Recorded in the task's handoff notes.
- **Trace.** The timeout resumes with `by: {"channel": "deadline", "on_timeout": …}` on `run_resumed`, visible in the
  span's raw events. The Audit log shows **Timed out**. No dedicated trace label was added; the handbook names both.
- **Social post review** approves on timeout ("publish unless the editor objects within a day"). Rejecting would
  send it to Rewrite and wait again, every day. The handbook says so.
- **Validator and the wait limit.** A deadline longer than `STUDIO_WAIT_TTL` (twice for escalation) is reported, so
  the global expiry never cuts a deadline short. With `STUDIO_WAIT_TTL=0` there is no limit.
- **Sweep cost.** One indexed query per second per worker, as with schedules.
- **Unrelated local failure.** `tests/test_code_node.py::test_time_limit_and_cancel_stop_the_call` fails locally on
  `develop` too: the local Docker takes 16 s to stop a 1 s Code call. CI is the reference.
