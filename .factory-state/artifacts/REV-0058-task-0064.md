### Non-Blocking

- **Templates reworked on the owner's feedback (2026-10-21).** The first version had five templates that differed only
  in the channel. They are replaced by real processes, each on a channel that fits it:
  - Slack: Refund approval;
  - Microsoft Teams: Leave request;
  - Telegram: Social post review;
  - WhatsApp: Large order check;
  - E-mail: Expense claim;
  - Slack, then e-mail: Purchase request.

  Support with escalation and Customer feedback digest complete the set. All five channels still appear, and no two
  graphs are the same.
- **Social post review loops back.** A reply other than `approved` (the editor's notes) goes to Rewrite and back to the
  editor. This is a cycle through a Condition, which the validator allows. Every pass waits for the editor, so it never
  loops on its own.
- **Large order check, offline.** The Decision mock picks `review` (the first label), so a mock run waits for the
  manager and shows the channel step.
- **Fixed an existing leak in `sanitize`.** Saving or exporting a template used to keep a Human node's whole
  `approval`, including the connection id, target and approver e-mails, while the docs and the save dialog said
  approval channels were removed. It now keeps only the kind (`{"channel": "slack"}`), or `{}` without one. The same
  rule REQ-0040 sets for built-ins now covers every template. A test covers it, and the dialog text and the handbook
  now say "connections and approvers".
- **Duplicated English text.** Built-in English names live in `templates.py`, which is used by the API and the export
  file, and in `en.json`, which the UI uses. The gallery falls back to the API text when a key is missing. Keeping
  both is the price of en/vi parity; a backend test pins the IDs.
- **Support with escalation** cannot run until a knowledge base is picked, like **RAG Q&A**. The offline run test
  skips it on purpose, and the handbook says so. Its graph is validated: the only error left is "choose a knowledge
  base".
- **Decision mock.** Offline, the Decision node picks `answered` (the first label) unless the answer text contains
  `escalate`, so a mock run ends without the review step. This matches DEC-0039's mock and is expected.
- **No logos on template cards.** The owner removed them before the merge (2026-10-21). The `channels` field on
  template summaries and `engine/templates.channels` were only there for those logos, so they were removed too (KISS).
  The API is back to its previous shape.
