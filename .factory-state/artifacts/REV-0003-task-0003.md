## Summary of Changes

- Backend (`backend/app/auth.py`, `backend/app/main.py`)
  - Password rules: ≥8 chars, letter + digit, ≤128. The seeded demo user is exempt.
  - Email normalised (trim, lowercase, ≤254). Login error stays generic.
  - An expired JWT returns 401 with `X-Auth-Error: expired`. `JWT_TTL_SECONDS` is configurable.
  - `check_secret()` warns about the placeholder secret at startup and refuses it when `STUDIO_ENV=production`.
  - Workflow names are whitespace-collapsed, non-empty and ≤120 chars.
  - Rename to a name the owner already uses → 409.
  - Duplicate or new names get unique suffixes (`(copy)`, `(copy 2)`, …), trimmed to 120 chars.
- Frontend
  - `lib/api.ts`: `ApiError` with status. Network errors get a friendly message.
  - On a 401, `sessionExpired()` redirects to `/login?expired=1&next=…`.
  - `scheduleExpiry()` auto-logs out at the JWT `exp`, with a fix for the setTimeout overflow.
  - `App.tsx`: `Protected` checks the token's expiry client-side and preserves `next`.
  - `Auth.tsx`: expired notice, live password-rule checklist, confirm mismatch, disabled/busy submit, autocomplete attributes, safe `next` redirect (no open redirect).
  - `Workflows.tsx`: loading, load-error with retry, an empty state distinct from no-search-results, clear-search (button and Esc).
  - `Workflows.tsx` also: truncated long names with a tooltip, rename validation and server errors inline, delete errors inline, toast notice for duplicate.
  - `Editor.tsx`: not-found / forbidden page with a link back, save errors shown, run blocked with a notice when the token has expired.
  - `Editor.tsx`, WebSocket: close code 4401 shows an auth-expiry message, then redirects.
  - `vite.config.ts`: API/UI ports via env, used by E2E.
- Tests
  - `backend/tests/test_auth_hardening.py`: 13 cases.
  - `frontend/e2e/studio.spec.ts`: 5 Playwright tests.
  - `frontend/e2e/screenshots.spec.ts`: only runs with `SHOTS=1`.

## Findings

- Deferred by owner: login rate limiting / lockout (not implemented).
- The `next` param is restricted to same-origin paths, which blocks open redirect.
- The client-side JWT decode is advisory only. The server remains authoritative.
- 100+ workflows: the list endpoint still does one query per workflow for the last run (N+1). It is acceptable at the tested scale (121 rows < 1.5 s in tests), but it is a candidate for TASK-0004/TASK-0009.
- Remaining lint warning in `Editor.tsx` (`useCallback` deps) predates this task.

## Risks

- Existing users with weak passwords can still log in; the rules apply only on register.
- E2E is not in CI yet: Actions is blocked by account billing, and adding a CI job was optional.
